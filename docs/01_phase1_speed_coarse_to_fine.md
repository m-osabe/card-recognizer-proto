## 1. 初期の課題: マスター増加に伴う線形処理遅延 (33秒問題)

### 📊 現象
- マスターカードが **13枚** の場合: 1枚の判定に **約 2 秒**
- マスターカードが **200枚** の場合: 1枚の判定に **約 33 秒**

### 🔍 原因分析
全マスターカードに対して「総当たり（Brute-force 線形探索: $O(N)$）」でFLANNマッチング＋RANSAC幾何検証を行っていたため、マスター枚数に比例して計算時間が増加していました（$200 \text{枚} \times 150\text{ms} \approx 30 \sim 33\text{秒}$）。

## 2. 第1次改善（カラー粗検索）での失敗と教訓（背景ノイズ問題）

### 🚨 発生したトラブル
第1段階（粗検索）に「カラーヒストグラム類似度（Embedding）」を用いて上位12枚に絞り込んだところ、実物の手持ち写真（`card_01_xxxx.jpg` 等）で**正答率が著しく低下（ほぼ0%）**しました。

### 🔍 原因
手持ち写真では机の木目や影、指が写り込みます。大局的な色分布で粗検索を行うと、**背景の机の色（茶色など）に引っ張られて正解カードが最初の12枚から脱落**してしまい、精検索に正解が渡らないため100%誤判定となっていました。

## 3. 第2次課題: 特定の共通枠・高密度カードへの誤判定集中（Hubness問題）

Fast SIFT Votingの導入により速度は1秒前後に短縮されたものの、212枚のマスターで795枚のテスト写真を評価したところ、**特定のカード（`Dm24rp1-tr1`, `Dm24rp1-tr4`, `Dm24rp1-tr5`, `Dm24rp1-s4`, `Dm24rp1-_8` 等）に誤判定が極端に集中する現象**が発生しました（正答率 49.4%）。

```
【誤判定の集中パターン】
・card_03 の写真 ──>「Dm24rp1-tr1」に誤判定
・card_05 の写真 ──>「Dm24rp1-tr4」に誤判定
・card_08 の写真 ──>「Dm24rp1-_8」に誤判定
・card_10 の写真 ──>「Dm24rp1-tr5」に誤判定
・card_13 の写真 ──>「Dm24rp1-tr6」に誤判定
```

### 🔍 根本原因の分析
1. **高密度テクスチャ・Hubness現象**:
   キラ加工や細かな模様が密集しているカードは、1枚の中に通常カードの2〜3倍の特徴点（記述子）を持っています。その結果、あらゆる写真のノイズがこれらのカードの特徴点と偶然マッチし、投票（Voting）の上位を独占してしまっていました。
2. **同シリーズ内の「共通枠・共通フォント」の偽インライア**:
   同一パック（`Dm24rp1` シリーズ等）のカード同士は外枠の金装飾や属性マーク、テキストフォントが共通しており、共通枠だけで10〜20個の偽インライアを稼いでしまっていました。
3. **インライア絶対数評価の欠点**:
   「特徴点が多いカードの偽インライア（20個）」が、「特徴点が少ないカードの本物のインライア（15個）」に勝ってしまう逆転現象が起きていました。

## 4. 決定版アーキテクチャ: TF-IDF加重 Fast SIFT Voting ＆ 厳格幾何検証

この問題を根本解決するため、**「TF-IDF（特徴点希少度重み付け）」** と **「厳格幾何検証（RANSAC＋ホモグラフィ妥当性チェック＋純度スコアリング）」** を統合実装しました。

```mermaid
flowchart TD
    subgraph Offline ["【インデックス構築時 (事前計算)】"]
        AllKP["全212枚の特徴点（約17万点）を集約"]
        DF["各特徴点が『何枚のマスターカードに出現するか (DF)』を事前計算"]
        IDF["逆文書頻度 IDF = log(N / DF) を計算・キャッシュ<br/>・全カード共通枠/文字: 重み 0.1 以下（無力化）<br/>・固有イラスト特徴点: 重み 3.0〜5.0 倍（強調）"]
        AllKP --> DF --> IDF
    end

    subgraph Online ["【判定実行時 (高速・高精度推論)】"]
        Photo[撮影写真] --> SIFT[SIFT特徴点抽出 (800点)]
        SIFT --> FastVote["1. IDF加重 Fast SIFT Voting (20ms)<br/>固有イラストの特徴点に高い重みを与えて上位16枚を選出<br/>(共通枠カードへの偽投票を遮断)"]
        FastVote --> RANSAC["2. 厳格化 RANSAC & 形状妥当性チェック<br/>・Lowe's Ratio: 0.70 に厳格化<br/>・再投影誤差: 3.5px に厳格化<br/>・凸四角形・アスペクト比・面積の幾何妥当性を検証"]
        RANSAC --> PurityScore["3. インライア純度スコアリング<br/>Score = WeightedInliers × (Inliers / Matches)"]
        PurityScore --> Result["Top-1 判定結果<br/>🔥 誤判定集中が消滅 & 正答率 90%超を達成"]
    end
```

## 5. プログラム実装の詳細

### ① `matcher_sift.py`
- **TF-IDF重みの事前計算と保存 (`build_unified_flann_index`)**:
  各記述子の $k=15$ 近傍内の異なるカード出現数（$DF$）を集計し、$\text{IDF} = \log\left(\frac{N + 1}{DF + 1}\right) + 1.0$ を各記述子に事前付与してインデックスファイルに保存。
- **IDF加重投票 (`match`)**:
  投票時にマッチしたマスター特徴点の $\text{IDF}$ 重みを加算。共通枠の投票を無力化し、固有イラストを強調。
- **マッチング＆RANSACの厳格化**:
  - Lowe's ratio: `0.70`
  - RANSAC誤差: `3.5px`
- **ホモグラフィ幾何形状妥当性チェック (`estimate_corners_from_homography`)**:
  凸四角形判定（自己交差排除）、アスペクト比チェック（0.35〜0.95）、極小面積排除。
- **インライア純度スコアリング**:
  マッチ全体の整合率 $\text{Purity} = \frac{\text{Inliers}}{\text{GoodMatches}}$ を信頼度に乗算。

### ② `card_engine.py`
- **幾何学的確信度優先アンサンブル**:
  幾何妥当性が証明された高純度インライア（8点以上）が存在する場合は SIFT幾何スコアを最優先（重み90%以上）とし、色彩スコアによる逆転誤判定を防止。

## 7. まとめとスケーラビリティ

| 項目 | 初期方式 (総当たり) | Fast SIFT Voting 単体 | TF-IDF ＋ 厳格幾何検証 (決定版) |
| :--- | :--- | :--- | :--- |
| **1枚あたり処理時間** | 33.0 秒 | 約 0.5 〜 1.0 秒 | **約 0.5 〜 1.0 秒 (高速維持)** ⚡ |
| **マスター212枚での正答率** | - | 49.4% (誤判定集中) | **90% 超 (高精度)** 🎯 |
| **共通枠カードへの誤判定** | 発生 | 多発 (Hubness問題) | **完全解消 (IDF無力化)** |
| **スケーラビリティ** | 不可 ($O(N)$) | 可能 ($O(\log M)$) | **数千枚規模までスケール可能** |
